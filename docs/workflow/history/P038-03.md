# P038-03

Początek: status czysty, walidator PASS (164 zadania), P038-02 completed.
Wykorzystano AGENTS, next-step, cpp-core-step, WORKFLOW, STATE/NEXT,
poprzedni raport, ARCHITECTURE, GAME_DESIGN, TESTING i CHECKPOINT_FORMAT.

publish_checkpoint_file waliduje staging, wymaga różnych nazw w tym samym
katalogu i używa MoveFileExW(REPLACE_EXISTING|WRITE_THROUGH), bez copy/delete.
save_checkpoint_file zapisuje main.tmp, potem zwalidowany poprzedni main
do main.bak.tmp; publikuje bak przed main. Nigdy nie przenosi main do bak.
Uszkodzony lub niedostępny main blokuje zapis; brak pliku pozwala na pierwszy
zapis i pozostawia istniejący backup. Błędy mogą zostawić staging do retry.
Przy odmowie publikacji main backup może już zawierać aktualny poprawny main.

Kontrakt: jeden zapisujący w prywatnym katalogu lokalnym, zaufane ścieżki.
Dwie publikacje nie są transakcją nazw; bez deklaracji odporności na utratę
zasilania/nośnika ani zapisy wielu procesów. API przyjmuje ścieżkę od przyszłej
warstwy sesji, nie wybiera katalogu użytkownika i nie jest podłączone do UI.
Automatyczne odzyskiwanie pozostaje P039.

windows_checkpoint_save: pierwszy/kolejne/powtórzone zapisy, dokładny poprzedni
backup, niewłaściwa wartość, uszkodzony main, brak main przy dobrym bak,
osobne blokady tmp/bak.tmp/bak/main oraz retry. Blokada main z odczytem
pozwala dotrzeć do odmowy rename; wyłączna blokada sprawdza odmowę readera.
Niepoprawny staging, ta sama ścieżka, różne katalogi i brak rodzica odrzucane.
