Data: 2026-11-10. Zależność P000 ukończona. Zakres: jedna udokumentowana inwentaryzacja, bez implementacji builda i gry.

## Wynik i decyzja

Dodano [TOOLCHAIN.md](../../TOOLCHAIN.md) z lokalizacjami, wersjami, komendami i ograniczeniami. Dostępne są CMake/CTest 3.26.4, clang-format 16.0.4, VS Build Tools 2022 17.14.40, MSVC x64 19.44.35228 (toolset w katalogu 14.44.35207), Windows SDK 10.0.22621.0 i MSBuild 17.14.51.32402. Dodatkowy CMake/CTest z VS ma wersję 3.31.6-msvc6.

Brak `cl`, `link`, `rc` i MSBuild w początkowym PATH wynika z niezaładowanego środowiska VS. Uruchomienie `VsDevCmd.bat` w procesie potomnym udostępnia narzędzia x64. vswhere działa przez pełną ścieżkę. Nie wykryto blokady narzędziowej P002; rzeczywisty build pozostaje jego kryterium. Niczego nie instalowano, nie pobierano ani nie zmieniano globalnego PATH lub konfiguracji Git.

## Weryfikacja

Dokładne komendy wersji, vswhere, środowiska VS i kontroli plików podano w TOOLCHAIN.md. Wyniki:

- `Get-Command` przed i po `VsDevCmd.bat -no_logo -arch=x64 -host_arch=x64`: potwierdzono różnicę pomiędzy brakiem PATH a instalacją; host i target to x64.
- `cmake --version`, `ctest --version`, `clang-format --version` oraz `--version` CMake/CTest z VS: exit 0, wersje jak wyżej.
- vswhere `-version '[17.0,18.0)' -products '*' -format json -utf8`: kompletna, uruchamialna instalacja 17.14.37628.2, bez wymaganego restartu. Wykrywanie `-requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64 Microsoft.VisualStudio.Component.VC.CMake.Project` zwróciło katalog BuildTools.
- `cmake -E capabilities` dla obu znalezionych CMake: exit 0; każdy zgłasza generator `Visual Studio 17 2022` oraz obsługę x64 i toolsetu.
- `cl.exe /Bv` w środowisku VS: wypisał kompilator 19.44.35228 i linker 14.44.35228.0, następnie **exit 2 / D8003** z powodu braku źródła. Nie jest to zaliczony build ani awaria wykrywania instalacji.
- `MSBuild.exe -version -nologo` w środowisku VS: exit 0, 17.14.51.32402.
- Odczyty wersji plików `cl.exe`, `link.exe`, `rc.exe`, domyślnego toolsetu, katalogów SDK i rejestru KitsRoot10: zgodne z tabelą TOOLCHAIN.md. Osiem kontroli `Test-Path -PathType Leaf` nagłówków i bibliotek MSVC/SDK: wszystkie `True`.
- `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Validate-Project.ps1`: PASS przed zmianą i po aktualizacji dokumentacji; 115 zadań, stan, przekazanie, odnośniki, skills i rejestry.
- `git -c safe.directory=D:/ThisGameMakesSteamAITagCompletelyUseless diff --check` oraz `diff --cached --check`: PASS przed commitem.

Nie uruchamiano builda ani CTest Debug/Release: projekt nie ma jeszcze CMake ani kodu C++. Nie zmieniano zachowania walidatora, więc nie powtarzano jego 11 przypadków regresyjnych. Początkowe `git status --short` zgłosiło dubious ownership; użyto istniejącej reguły procesowej `-c safe.directory=...`, bez zmiany ustawień globalnych. Status z tą opcją był czysty przed zmianami.
