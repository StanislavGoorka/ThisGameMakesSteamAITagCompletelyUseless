## Kontrakty przekazane implementatorom

- Hash ma używać FNV-1a 64-bit z jawnie określonym kodowaniem v1 wszystkich pól, stałych szerokości little-endian, tagów optional i liczby elementów. Kolejność przechowywania impulsów jest częścią dokładnego stanu, zgodnie z same_state; hash nie sortuje i nie mutuje. Nie haszuje surowej pamięci ani std::hash. Wektory muszą być obliczone niezależnie. Hash jest niekryptograficzny, a testy różnicowania korpusu nie dowodzą braku kolizji.
- Fabryka jest narzędziem headless poza core i paczką gry. Stały kwadrat pól 0/1/7/8 ma maski E|S, W|S, N|E, N|W; gracz0, wejście0, odbiorniki1/8, wyjście8, impuls ID1 na7, HP3 i tura0. Tylko węzeł1 jest obrotowy. Lokalny SplitMix64 wybierze 0–3 jego początkowe obroty; reszta stanu jest stała. To niewyświetlane dane syntetyczne, nie generator sektorów P028, certyfikat rozwiązania ani obietnica wygrywalności. Wiele seedów może dać ten sam fixture.
- Runner ma przyjmować wartościowe version/seed/komendy. Obsługiwana wersja1 obejmie reguły, fixture i format hasha. Nieobsługiwana wersja ma dać jawną odmowę bez częściowego wyniku. Istniejący resolver pozostaje jedyną implementacją tury. Ślad zawiera hash początkowy i accepted/outcome/hash po każdej próbie; odrzucone komendy zachowują hash i nie przerywają kolejnych prób, również po terminalnym wyniku. Wynik końcowy posiada niezależny GameState. Nie ma usług zapisu lub RNG w resolverze.
- CLI ma przyjmować dziesiętne version seed i opcjonalne tokeny wait, move:NodeId, rotate:NodeId. Najpierw waliduje całe wejście, potem uruchamia runner. Diagnostyka i numeryczny ślad są deweloperskie. Brak argumentu, trailing junk, minus, przepełnienie, NodeId49, zły token i nieobsługiwana wersja dają niezerowy kod bez częściowego śladu sukcesu. Nie powstaje format zapisu gry lub import JSON.

Każde dziecko ma kryteria pozytywne, właściwe przypadki błędów i celową mutację produkcyjną z wymuszonym Rebuild. [NEXT](../NEXT.md) podaje pełny format bajtów i zakres wyłącznie P024-01; nie implementuje przyszłych dzieci.
