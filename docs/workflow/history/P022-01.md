# P022-01 — Wyjście i niemutująca klasyfikacja sektora

Data 2026-11-11. Początkowy HEAD `ed7e8d2`, drzewo czyste. Zależność P022 ukończona jako podział planu. Walidator początkowy zaliczył 127 zadań.

## Rezultat

Dodano opcjonalny GameState::sector_exit, z pustą wartością początkową i bez zmiany sygnatury initial. Test sprawdza zachowanie niepustego wyjścia w dwóch kolejnych kopiach oraz niezależne ustawienie NodeId 0 i usunięcie wyjścia. Wszystkie 14 dotychczasowych helperów same_state porównuje nowe pole; ich fabryki zawierają wyjście 48, aby chronić je przed zerowaniem.

[sector_outcome.hpp](../../../src/core/sector_outcome.hpp) dodaje SectorOutcome z ongoing/completed/death/overload oraz sector_outcome(const GameState&). HP=0 zawsze daje death. Żywy gracz na istniejącym wyjściu wygrywa z co najmniej dwoma indeksami mającymi obie flagi receiver_nodes i powered_nodes, najpóźniej na turze 48. Sukces na turze 48 wyprzedza przeciążenie. Bez sukcesu co najmniej 48 tur daje overload; wcześniej sektor trwa. Po limicie nie można otrzymać spóźnionej wygranej.

Wynik jest wyliczany bez trwałego pola i dodatkowego licznika dostaw. Funkcja czyta tylko potrzebne dane i nie wykonuje kontaktu, dostawy ani fazy. Nie zmieniono TurnResult, resolve_turn, is_command_legal ani niskopoziomowych helperów. Resolver jeszcze nie egzekwuje końca sektora.

## Testy i weryfikacja

Nowy [test](../../../tests/unit/sector_outcome_tests.cpp) zarejestrowano w trzech miejscach CMake. Macierz obejmuje wyjścia 0/48, brak wyjścia i inną pozycję, HP 0/1/3, zero/jedną/dwie dostawy oraz tury 0/47/48/49 i maksymalny licznik. Osobne scenariusze chronią przed liczeniem zasilonych nieodbiorników i zaliczeniem jedynego istniejącego odbiornika jako dwóch dostaw. Pakiet na celu nie jest automatycznie dostarczany, a impuls na żywym graczu nie rozwiązuje kontaktu. Każdy odczyt powtarza się trzykrotnie i porównuje cały stan z niepustym pakietem, impulsami i pozostałymi danymi.

Wykonano z katalogu repozytorium:

```powershell
$files = @(rg --files src tests | Where-Object { $_ -match '\.(hpp|cpp)$' })
clang-format --style=file -i @files
cmake --preset windows-msvc
cmake --build --preset windows-debug
ctest --preset windows-debug --output-on-failure
powershell -NoProfile -ExecutionPolicy Bypass -File .local/Test-P022-01Mutation.ps1
cmake --build --preset windows-debug
ctest --preset windows-debug --output-on-failure
cmake --build --preset windows-release
ctest --preset windows-release --output-on-failure
clang-format --style=file --dry-run --Werror @files
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Validate-Project.ps1
git -c safe.directory=D:/ThisGameMakesSteamAITagCompletelyUseless diff --check
git -c safe.directory=D:/ThisGameMakesSteamAITagCompletelyUseless diff --cached --check
```

Konfiguracja i buildy MSVC x64 przeszły. Początkowy Debug oraz końcowe Debug i Release zaliczyły po **23/23 CTest**. Formatter wszystkich źródeł, walidator **127 zadań** i kontrole diff przeszły.

Celowa mutacja zastąpiła warunek receiver_nodes[index] && powered_nodes[index] samym powered_nodes[index]. Wrapper wymusił `cmake --build --preset windows-debug --target core_sector_outcome_tests -- /t:Rebuild` i sprawdził rekompilację sector_outcome_tests.cpp. `ctest --preset windows-debug --output-on-failure -R '^core_sector_outcome$'` zwrócił oczekiwany kod **8** i komunikat `Powered nonreceivers must not count as deliveries`. W finally przywrócono oryginalne bajty nagłówka i ponownie wymuszono oraz sprawdzono rekompilację. Wrapper zakończył się kodem 0. Ignorowane logi: .local/P022-01-mutation-build.log, .local/P022-01-mutation-test.log, .local/P022-01-restored-build.log; wrapper pozostaje poza commitem.
