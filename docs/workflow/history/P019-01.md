# P019-01 — Reprezentacja i zajęcie impulsów

Data 2026-11-11. Zależność P019 ukończona jako podział planu, a P018-03 zaimplementowane. Na początku drzewo robocze było czyste (HEAD `7c8583f`); walidator zaliczył 121 zadań.

## Rezultat

`GameState::pulses` jest wartościowym `std::vector<Pulse>`, początkowo pustym. `Pulse` zawiera silny `EntityId id` i `NodeId position`, z porównaniem wartości. Sygnatura `GameState::initial` pozostała bez zmian. Poprawny stan ma unikalne ID i najwyżej jeden impuls na polu; gracz i pakiet mogą współdzielić z nim pole. Te warunki opisano w komentarzu i architekturze; nie dodano fabryki spawnu ani walidatora sektora. [Stan gry](../../../src/core/game_state.hpp)

Nowy `pulse_occupies(const GameState&, NodeId)` jest predykatem `constexpr`, `noexcept`: odczytuje wyłącznie pozycje impulsów i nie mutuje stanu. Nie powiela zajęcia w `blocked_nodes`. Kod ruchu gracza pozostał bez zmian: połączenie na pole impulsu pozwala wejść, a osobna flaga blokowania nadal odrzuca ruch. Kontakt nie zadaje jeszcze obrażeń i nie usuwa impulsu. [Predykat](../../../src/core/pulse_occupancy.hpp)

## Pliki i testy

Nowy [pulse_occupancy_tests.cpp](../../../tests/unit/pulse_occupancy_tests.cpp) rejestruje `core_pulse_occupancy` w trzech miejscach [CMake](../../../CMakeLists.txt). Predykat sprawdzono dla każdego pola 0–48, trzykrotnie na pole, w pustej i niepustej kolekcji. Zajęte są 0, 24 i 48, z różnymi ID, w tym granicami `EntityId`. Odwrócenie kolejności jednostek i zmiana portów, blokowania, integralności oraz licznika tur nie zmieniają zajęcia. Pełny stan przed i po jest porównywany.

[Testy stanu](../../../tests/unit/game_state_tests.cpp) sprawdzają pustą kolekcję po inicjalizacji oraz dwie kolejne kopie niepustego stanu. Zmiana ID, pozycji i usunięcie elementu kopii zachowują pozostałe kolekcje. [Testy ruchu gracza](../../../tests/unit/player_movement_tests.cpp) potwierdzają wejście na impuls współdzielący pole z pakietem bez innych zmian; osobna flaga `blocked_nodes` odrzuca to samo wejście i zachowuje stan.

Do siedmiu istniejących helperów `same_state` dopisano `pulses`: `player_movement`, `player_rotation`, `player_wait`, `packet_movement`, `packet_delivery`, `packet_target`, `packet_introduction`. Ich fabryki tworzą niepustą kolekcję, aby dotychczasowe kroki nie mogły jej po cichu wyzerować. README i architektura opisują stan rzeczywisty i pozostawiają wybór kroku oraz ruch do P019-02/P019-03.

## Weryfikacja

Konfiguracja MSVC x64, build i CTest Debug/Release zaliczone: **16/16 w obu konfiguracjach**. Po mutacji wykonano pełny `/t:Rebuild` Debug, aby wykluczyć starą binarkę.

```powershell
cmake --preset windows-msvc
cmake --build --preset windows-debug
ctest --preset windows-debug --output-on-failure
# Po przywróceniu mutacji:
cmake --build --preset windows-debug -- /t:Rebuild
ctest --preset windows-debug --output-on-failure
cmake --build --preset windows-release
ctest --preset windows-release --output-on-failure
clang-format --style=file --dry-run --Werror (rg --files src tests -g '*.hpp' -g '*.cpp')
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Validate-Project.ps1
git -c safe.directory=D:/ThisGameMakesSteamAITagCompletelyUseless diff --check
git -c safe.directory=D:/ThisGameMakesSteamAITagCompletelyUseless diff --cached --check
```

Celowy błąd zamienił w predykacie `pulse.position == position` na `!=`. Pole wolne 1 zostało wtedy błędnie zgłoszone jako zajęte. Komenda `cmake --build --preset windows-debug --target core_pulse_occupancy_tests -- /t:Rebuild` pokazała rekompilację `pulse_occupancy_tests.cpp`. Następnie `ctest --preset windows-debug --output-on-failure -R '^core_pulse_occupancy$'` odrzucił mutację kodem 8 i komunikatem `Pulse occupancy must match the collection and preserve the entire state at node 1`. Nagłówek przywrócono w bloku `finally` przed końcowymi testami.

Formatter, walidator projektu (121 zadań) i kontrole diff przeszły. Nie dodano assetów, napisów ani innych treści dla gracza. Próba uruchomienia Pythona do edycji plików nie powiodła się (niedostępny `python.exe`); edycje wykonano w PowerShell, bez instalacji narzędzi i bez zależności projektu od Pythona.
