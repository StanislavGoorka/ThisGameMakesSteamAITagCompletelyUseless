# P002 — minimalny build core

Data: 2026-11-10. Zależność P001 ukończona. Zakres: jeden build C++20 i jeden test CTest, bez mechanik i treści gry.

## Wynik i decyzja

Dodano `CMakeLists.txt` (CMake 3.26+) i `tests/unit/build_tests.cpp`. Cel `game_core` jest biblioteką INTERFACE przekazującą wymaganie C++20; nie dodano sztucznej funkcji produkcyjnej tylko na potrzeby builda. Runner `core_tests` korzysta z tego celu, a `core_build_smoke` jest jego jedyną rejestracją w CTest. Test porównuje podwidok `std::span` przez `std::ranges::equal`; jawnie zwraca 1 i diagnostykę przy błędzie, bez `assert`. Diagnostyka jest wyłącznie narzędziem deweloperskim, nie tekstem gry.

CMake wyłącza rozszerzenia języka; runner MSVC ma `/W4` i `/permissive-`. `BUILD_TESTING` pochodzi z CTest. Nie dodano zależności, presetów, CI ani konfiguracji stylu z P003. Nie pobierano assetów. Zaktualizowano README, opis aktualnych testów, STATE i NEXT.

## Weryfikacja

Wszystkie komendy wykonano w PowerShell z `D:\ThisGameMakesSteamAITagCompletelyUseless`. Początkowy status z procesowym `safe.directory` był czysty. Pierwsze wywołanie bez tej opcji zgłosiło dubious ownership; nie zmieniano globalnej konfiguracji Git.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Validate-Project.ps1
clang-format --style="{BasedOnStyle: LLVM, IndentWidth: 4, BreakBeforeBraces: Allman}" -i tests/unit/build_tests.cpp
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Debug
ctest --test-dir build -C Debug --output-on-failure
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

Wszystkie powyższe komendy: exit 0. Walidator: PASS, 115 zadań. CMake wykrył MSVC 19.44.35228.0 i Windows SDK 10.0.22621.0. Kompilacja i linkowanie przeszły w obu konfiguracjach; CTest: 1/1 PASS w każdej. CMake sam wykrył VS; nie zmieniano PATH i nie trzeba było uruchamiać VsDevCmd.

Test negatywny: tymczasowo zmieniono oczekiwaną tablicę z `std::array{2, 3}` na `std::array{2, 4}`. Dla każdej konfiguracji uruchomiono poniższą pętlę; jej końcowy exit 0 potwierdza dokładnie oczekiwane kody błędów:

```powershell
foreach ($configuration in @('Debug', 'Release')) {
    cmake --build build --config $configuration
    if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
    & "./build/$configuration/core_tests.exe"
    $runnerExit = $LASTEXITCODE
    Write-Output "$configuration runner exit: $runnerExit"
    ctest --test-dir build -C $configuration --output-on-failure
    $ctestExit = $LASTEXITCODE
    Write-Output "$configuration CTest exit: $ctestExit"
    if ($runnerExit -ne 1 -or $ctestExit -ne 8) { exit 1 }
}
exit 0
```

Debug i Release: build exit 0, runner exit **1**, CTest exit **8**, 0/1 PASS i oczekiwana diagnostyka `C++20 span/ranges smoke test failed`. Potwierdza to wykrywanie błędu również przy optymalizacji Release.
